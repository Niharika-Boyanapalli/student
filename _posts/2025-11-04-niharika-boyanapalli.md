# Blog — Niharika Boyanapalli  
Date: 2025-11-04

## Overview
This post summarizes what I learned over recent sprints, compares my current skills to the start of the year, reviews feedback and analytics, and outlines what I want to do next. I focus on three main efforts: the Tool Sprint, the Teaching Fundamentals of JS Sprint, and the Gamify Mansion Sprint. I also reflect on how N@TM went and highlight a few actionable next steps.

## Where I am vs. the beginning of the year
At the start of the year I was very uncomfortable with basic programming concepts and small projects and less confident in planning multi-week sprints, and collaborating. Now I am better at:
- shipping end-to-end features more consistently (design → prototype → user testing → iterate)
- using version control and issue tracking more effectively
- reading and acting on simple analytics to prioritize fixes and features

My confidence improved most in project scoping and user-focused iteration.

## Tool Sprint — key takeaways and classification
What we learned:
- Importance of small, reliable developer tools to speed iteration (vscode.dev, GitHub, Kasm, etc.).
- How to manage files, commit changes, clone accounts, and complete pull requests.

Classification: This sprint was primarily focused on learning and using the tools effectively.

## Teaching Fundamentals of JavaScript Sprint — what we learned
What we taught and learned:
- Core JS topics (arrays, booleans, variables, functions).
- Explaining concepts forces deeper understanding; teaching solidified my understanding.

## Gamify Mansion Sprint — summary and classification
What we built:
- A small gamified interactive experience with progressive challenges and feedback loops.
- Mechanics: using core JavaScript topics, understanding game mechanics, collaboration and organization, etc.

What I learned:
- Balance between challenge and reward is key for engagement.
- I also learned how to use code effectively.

## How N@TM went
We presented a demo at N@TM (our group showcase). Highlights:
- The demo ran smoothly in the controlled environment.
- Audience interest was strongest around the gamification features and how API code was used.
- Quick live feedback on our mansion demo helped prioritize small fixes for the next term.
- A comment we liked: big scope and good execution.

## What I want to do on the next project
- Build a multiplayer or social feature to add on to our game.
- Add progression levels so level 2 unlocks after completing level 1.
- Improve speed and clarity of the game.

## Time given for our project — reflection
Time felt tight but manageable. For our next project, this amount of time seems ideal.

## What I want to learn next in computer science
- Deeper algorithms and data structures.
- Networking basics for multiplayer features.
- More game code to deepen understanding.
